This report presents my Week 2 work on data collection, cleaning, and preprocessing for an ecommerce logistics analysis project. It continues the delivery-reliability scenario developed in Week 1 and documents an executed Python workflow using four public tables from Olist’s official GitHub repository.

The work covers 99,441 orders, 112,650 order items, 99,441 customer records, and 32,951 products. The report explains how source files were recorded, identifiers and data types were checked, missing values were measured, and item records were aggregated before joining them to orders. It also documents inconsistent delivery milestones, missing product information, and invalid physical values, with clear reasons for each treatment.

All source orders were retained in an audit table. A separate matrix of 86,484 eligible approval records was prepared with 54 numeric feature columns. Numeric imputation, outlier thresholds, normalization parameters, and categorical vocabularies were fitted only on the training period and applied consistently to later periods. Missing outcomes were not invented, and legitimate extreme observations were retained.

Python examples illustrate validation, date parsing, aggregation, imputation, outlier detection, transformation, encoding, and export. Measured before-and-after examples and independent checks provide evidence of execution. The report concludes by explaining how data quality affects logistics decisions, identifying limitations, and describing the next analysis stage. It reports completed preprocessing and historical descriptive results without claiming that a prediction model was trained or that service performance improved.
